System layers

Presentation layer

The Flask templates and dashboard provide navigation, forms, status views, and accessible feedback. Browser state-changing requests include CSRF protection.

Identity layer

Flask-Login manages sessions. Passwords are stored as Argon2 hashes. Optional TOTP MFA adds a second verification step and lockout controls protect repeated failures.

Authorization layer

Roles control actions: administrators manage the platform, doctors can create clinical records and use break-glass, nurses and records officers have narrower workflows, and tier checks protect paid capabilities.

Clinical data layer

Patients and medical records are persisted through SQLAlchemy. Sensitive record fields are encrypted before storage and decrypted only for an authorized request.

Cryptography layer

Free uses AES-128-GCM. Pro and Enterprise use AES-256-GCM with versioned keys and scheduled rotation. Ciphertext retains its key version for controlled decryption.

Audit layer

Important actions are written to a hash-chained audit log. Break-glass, authentication, user, privacy, billing, API-key, backup, and maintenance events are reviewable.

Resilience layer

The maintenance scheduler creates encrypted .vwb SQLite backups and rotates Pro and Enterprise keys. Health checks report database, encryption, and maintenance status.

Integration layer

Provider-issued payment references are verified server-side before paid tier changes. API keys are scoped, shown once, hashed at rest, and revocable.

Records officerAuthorized patient and records administration without doctor-only emergency actions.

Security and privacy rules

  • Never share passwords, MFA codes, API keys, card details, or provider secrets.
  • Use the least-privileged role and API scope needed for the task.
  • Use break-glass only for a real emergency and write a precise reason.
  • Use encrypted backups and test restores in a disposable environment before relying on a recovery procedure.
  • Legal holds prevent eligible records from automated retention purge; privacy erasure decisions belong to authorized administrators.
  • Report suspected compromise through the incident workflow and preserve relevant audit evidence.

Operations checklist

SituationRecommended action
Daily startCheck System Resilience and Security & Activity for degraded health or unusual events.
Before a releaseCreate an encrypted backup, confirm the health endpoint, and review pending maintenance.
Suspected breachPreserve audit records, create an incident, restrict affected access, and follow INCIDENT_RESPONSE.md.
Data requestUse Privacy & Governance, verify identity and legal basis, then record the decision or hold.
Connected systemCreate one named API key with the smallest scopes, copy it once into the system secret manager, and revoke it when no longer needed.
